# Лабораторная работа №4. Многопоточное и асинхронное программирование

Наблюдение за каталогом в реальном времени: новые `.md`-файлы с анкетами
(формат ЛР2) попадают в потокобезопасную очередь и обрабатываются
многопоточно (пул потоков по числу ядер) или асинхронно (`std::async`).
Результат — нормализованная анкета — сохраняется в `l4_results/<сессия>/`.

## Соответствие заданию

| Пункт задания | Реализация |
|---|---|
| 1.1 Потокобезопасная «Очередь» на mutex | [thread_safe_queue.h](thread_safe_queue.h) |
| 1.2 Отдельный поток читает файлы каталога и добавляет в очередь, отслеживание в реальном времени | `Application::watch()` в [application.cpp](application.cpp) (системные уведомления + скан) |
| 1.3 Обработка файлов ЛР2/ЛР3 в многопоточном режиме, число потоков = число ядер | `Application::run()`, пул `workers_` = `hardware_concurrency` |
| 1.4 Интерактивные команды: a) очередь, b) результат файла, c) смена каталога, d) сброс результатов, e) сброс очереди | пункты меню 1–5 в [main.cpp](main.cpp) |
| 2.1 Асинхронная обработка через «Очередь» и функции обработки | режим 2: диспетчер `std::async` в `Application::schedule()` |
| 2.2 Отмена асинхронной операции по запросу | пункт 7 «отменить операцию по ID» |
| 2.3 Просмотр статуса выполнения по каждому файлу | пункт 6 «статусы всех файлов» |

## Структура

- `main.cpp` — консольный интерфейс (меню, выбор режима и каталога);
- `application.h/.cpp` — ядро: наблюдатель, пул потоков / диспетчер async, статусы, отмена;
- `thread_safe_queue.h` — потокобезопасная очередь (mutex + condition_variable);
- `file_processor.h/.cpp` — потоковая обработка анкет (алгоритмы ЛР2/ЛР3 из `legacy/`);
- `legacy/` — заголовки с алгоритмами ЛР2/ЛР3 (разбор Markdown, нормализация анкеты);
- `input/` — тестовые файлы-анкеты.

## Сборка

Быстрый способ — одной командой из папки `lab4`:

```
.\build.bat
```

Вручную через CMake (Ninja или Visual Studio):

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

В Visual Studio 2022: `cmake -S . -B build -G "Visual Studio 17 2022"` и открыть `build\Lab4.sln`.

> ⚠ Если в пути к проекту есть кириллица (например, `…\Технологии программирования\…`),
> генератор **MinGW Makefiles** не находит исходники из-за кодировки путей в Makefile —
> используйте **Ninja** (или Visual Studio). `build.bat` делает это автоматически.

Требования: CMake ≥ 3.16, компилятор C++17. На Windows с MinGW — `g++` и `ninja`
из MSYS2 UCRT64; `build.bat` сам добавляет `C:\msys64\ucrt64\bin` в PATH.

## Запуск

```
build\lab4.exe [каталог]
```

- режим **1** — многопоточная обработка (пул потоков);
- режим **2** — асинхронная обработка (`std::async`, отмена по ID);
- каталог по умолчанию — `input` (создаётся, если его нет).

Меню: 1 — очередь, 2 — результат по ID, 3 — сменить каталог,
4 — сбросить завершённые результаты, 5 — очистить очередь,
6 — статусы всех файлов, 7 — отменить операцию по ID, 0 — выход.

Файл ставится в очередь после ~300 мс «стабильности» (размер и время изменения
не меняются), поэтому частично скопированные файлы не обрабатываются. Результаты
пишутся в отдельную сессионную папку `l4_results/<время>_<n>/` и не затирают исходники.
